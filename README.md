# SQL Practice — 113 queries on real data (SQLite)

Interview-prep environment: five real Kaggle datasets loaded into five SQLite
databases, with 113 progressively harder queries that run and return real results.

**Verified: 113/113 execute, 0 errors, 0 empty results.** Every row and column of
all 11 source CSVs is loaded — nothing sampled or dropped.

## Quick start

Datasets and databases aren't in the repo (~1.1 GB, regenerable). Build once:

```bash
conda activate sqlPract
pip install -r requirements.txt
kaggle auth login                  # browser OAuth, one time

python scripts/fetch.py            # download 5 Kaggle datasets  -> data/raw/
python scripts/build.py            # CSVs -> 5 SQLite databases  -> db/
python scripts/run.py              # run all 113 queries         -> docs/RESULTS.md
```

Already built? `python scripts/run.py`. Then open any `db/*.db` in DBeaver or
VSCode SQLTools and work through `queries/`.

No Kaggle account? Download the five ZIPs by hand into `data/_incoming/` —
`fetch.py` matches them by filename. (The Kaggle client is 2.x and no longer
reads `kaggle.json`; use `kaggle auth login` or `~/.kaggle/access_token`.)

## Layout

```
queries/   01_ecommerce  02_churn  03_hr  04_food_delivery  05_fraud   (.sql)
scripts/   fetch → build → run       (+ profile_data, derive, sqlutil)
docs/      QUESTIONS.html · DATA_PROFILE.md · RESULTS.md
data/ db/  gitignored — regenerated by fetch.py and build.py
```

A query file maps to its database by its leading number
(`01_ecommerce.sql` → `db/project_1_ecommerce.db`); `run.py` finds them by glob.
Each database keeps the untouched source as `raw_*` tables beside the derived
ones, so any derivation can be checked against its source.

## Two things that will bite you

**Math functions.** Some queries use `sqrt()`, `power()` and `log()`. SQLite only
ships these when compiled with `SQLITE_ENABLE_MATH_FUNCTIONS`. Test with
`SELECT sqrt(4);` — the `sqlPract` env has them, and Anaconda's bundled `sqlite3.exe`
does not.

**The data is not what tutorials claim.** The fraud set has no merchants or
customers (only PCA components), the churn set has no `churn_date`, and the food
delivery set is essentially randomly generated. The queries were written against
what's actually there.
